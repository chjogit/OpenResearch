# 기업별 데이터 품질 검사 반영 안내

## 실행

압축을 풀고 OpenResearch_QualityAgents 폴더에서 실행합니다. Python 3.12 이상.

    python -m pip install -r requirements-quality-notebooks.txt
    python -m jupyterlab

1. notebooks/두_Agent_기본구현_Python_LLM.ipynb
   - 기존 Python 분석 앞에 기업·Agent별 품질 요약표와 규칙 상세표를 추가했습니다.
   - 기본은 합성 A기업, API·DB 없이 실행됩니다. 합성 자료 최신성은 미판정이며 일부 가능입니다.
   - run_checked를 통해 Python·데모·실제 Solar·ML/DL 확장 경로를 모두 연결했습니다.
   - 보류면 Agent 계산·LLM·선택 모델을 호출하지 않고 사유만 반환합니다.
   - 마지막 셀에서 관측 기간 부족에 따른 실행 차단을 확인합니다.
2. notebooks/Neon_기업별_데이터_현황.ipynb
   - .env의 DATABASE_URL에 읽기 계정 주소를 설정한 뒤 실행합니다.
   - 실제 DB 집계 뒤 기업별 두 Agent 준비 상태 표를 표시합니다.
   - 집계만 정상인 경우는 원문·달력·조정 검수가 남으므로 일부 가능으로 표시합니다.
   - 조회 실패·미보유·핵심 결측·기간 부족·오래된 시세는 보류합니다.

## 상태 의미

실행 가능(passed): 현재 검사 규칙 통과. 근거 진실성·투자 판단·공유 승인 완료가 아님.
일부 가능(partial): 한계·부족한 자료를 유지하며 가능한 분석만 진행.
보류(withheld): 해당 Agent 실행을 막고 보완 요청 반환.

## 검사 기준

- 기간: 지표 window 최소 관측 수, 보유 구간, 날짜 순서·중복·미래 시세 검사.
- 결측: 종가·거래량 NULL/비수치·음수 등 핵심 오류 차단. 전체 OHLC 미확보는 일부 가능.
- 최신성: 기본 시세 5달력일, 문서 400달력일 정책. 노트북 상단 상수로 변경 가능.
- 시점: QUALITY_REFERENCE_DATE / READINESS_REFERENCE_DATE를 실제 검사 목적의 기준일로 설정.
  고정 2026-10-27은 재현용 기본값입니다. 과거 분석이면 당시 시점을 명시하세요.
- 원문: 주장 연결 근거·위치·발췌·문서 식별자, 공개일과 자료 기준일 검사.
- 가격: 실제 자료는 조정 기준·설명 출처 필요. 공식 거래일·기업행위의 진위 대조는 별도.

합성 자료에 실제 거래일·최신성 통과를 부여하지 않습니다. 공개 품질 페이지의 API 신호등이나
샘플 fallback 값을 실제 데이터 품질로 사용하지 않습니다. API를 우회하거나 직접 호출하지 않았습니다.

## 구현 파일

agent/quality_gate.py: 보고서 기반 검사, 집계 기반 준비 표, 실행 차단 래퍼.
agent/data_inventory.py: 필드별 nullCounts를 추가해 핵심 종가/거래량 결측을 구분.
Agent 결과 qualityGate 필드에 기준일·규칙 버전·사유·검사 항목을 보존합니다.
자료 digest나 window가 바뀌면 기존 검사 결과를 사용할 수 없으며 검사를 다시 실행해야 합니다.
검사 객체는 애플리케이션 내부 제어용이며 서명된 권한 증명이 아닙니다.

## 실제 데이터 연결 경계

Neon 노트북은 집계표를 만들며 Agent 노트북에 원시 자료를 자동 적재하지 않습니다.
실제 실행하려면 검수된 원문·시세를 공통 report/evidence 구조로 변환하고 검사한 뒤 전달하세요.
최신 날짜만으로 중간 거래일 누락을 확정하지 않습니다. 공식 달력 CSV는 기존 Neon 노트북에서
별도로 지정하며, 원문 내용 검증·Peer 적합성·조정 계산·모델 정확도는 별도 검사입니다.

## 검증

기본 노트북 10개 셀 오프라인 실행, Neon 노트북 8개 셀 가짜 DB 실행.
전체 테스트 95개 및 변경 모듈 린트 통과. 실제 Neon·Solar·보호된 Vercel API는 호출하지 않았습니다.
