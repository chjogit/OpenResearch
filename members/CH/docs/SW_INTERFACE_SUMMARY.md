|---|---|---|

정의 위치: `members/CH/ch_agents/nodes.py`. 실행: `run_agent_nodes(agent_no, ticker, as_of, extension, available)`. 서술·검증·계약까지: `ch_agents.llm.run_node_agent(agent_no, ticker, ...)`.

## 호출·반환 스키마 (pydantic, 알 수 없는 필드 거절)
- NodeTask: `task_id`, `node_id`, `target_ticker`, `as_of_date`, `input_data_ids`, `parameters`, `constraints`
- NodeResult: `status`(SUCCESS / PARTIAL_SUCCESS / DATA_INSUFFICIENT / FAILED), `artifacts`, `evidence_links`, `missing_items`/`unresolved`, `execution_meta`, 확장 스킵 시 `prediction_skipped_reason`

## 규칙
- 모든 조회가 `as_of` 필수, 기준일 당일 포함·다음 날부터 제거. 진술 태그 Fact / Computation / Prediction / Interpretation. 상충 신호는 `conflicts`(평균 없음).
- 미확보 입력: 호가 잔량, 세부 투자 주체, 거시 수정 이력 — `missing_items` 로 표시.
- 데이터 계약 `r4-1.5`: r4-1.3 필드(`agent.agentNos`, `claims[].tag`, `nodes[]`, `nodeSummary`, `conflicts`, `predictionSkippedReason`) + **`outlook`**(아래). 기존 필드·상태값 불변, `outlook` 이 없는 옛 결과도 그대로 읽힘.

## 전망 결론 `outlook` (에이전트 3·4·6 각각, r4-1.4)
각 에이전트가 자기 영역의 **기준일 다음 거래일부터 20거래일 가격 방향**을 긍정·중립·부정으로 냅니다. 값은 **정해진 규칙**(규칙 버전 `outlook-r1`, 문서 `docs/OUTLOOK_RULES.md`)이 정하고 LLM 은 쓰지 않습니다. 매수·매도·보유 결론과 가격 수준은 없습니다.

예시 (삼성전자, 에이전트 4, 기준일 2026-11-04):
```json
"outlook": {
  "direction": "negative", "directionLabel": "부정", "horizonDays": 20, "startAfter": "2026-11-04",
  "reasonCode": null, "reason": null, "tag": "Prediction",
  "positiveFactors": [],
  "negativeFactors": [{"signalId": "flow_foreign", "text": "외국인 20일 순매수 강도 -4.34%: 순매도 우세(규칙 기준 초과)",
                       "template": "외국인 20일 순매수 강도 {S4}: 순매도 우세(규칙 기준 초과)", "tag": "Computation", "evidenceKeys": ["S4"], "evidenceIds": []}],
  "signals": [{"id": "flow_foreign", "state": "negative", "...": "..."}, {"id": "flow_institution", "state": "neutral", "...": "..."}],
  "ledger": {"S4": {"label": "외국인 20일 순매수 강도(거래대금 대비)", "value": -4.34, "display": "-4.34%", "dataDate": "2026-11-03"}},
  "hitRate": {"status": "unverified", "rate": null, "n": null, "reason": "측정 전 (적중률 결과 파일 없음 — #55)", "text": "과거 적중률: 미검증 (측정 전 …)"},
  "ruleVersion": "outlook-r1.1", "limit": "수급 자료는 시세보다 하루 늦게 적재됨 …", "note": "세 에이전트 결론의 종합은 오케스트레이터(SW) 담당입니다 …"
}
```
- **`hitRate.verdict`(`edge`·`indistinct`·`unverified`) + `verdictLabel` + `notice`**(#58): 판정이 `edge`(기준선 대비 우위 있음)가 아니면 **종합 가중에 쓰지 말 것**. 현재 에이전트 4·3 은 `indistinct`(기준선과 구별 안 됨), 에이전트 6 은 `unverified`. `notice` 는 화면에 그대로 붙일 고정 문구입니다. 판정 규칙은 `docs/OUTLOOK_BACKTEST.md` 5-1.
- (#76, 11/9) 규칙 버전 `outlook-r1.1`: 에이전트 6 감성 변화 비교 창이 '직전 7일(8~14일)'로 바뀜(장부 라벨 `…감성 변화(최근 7일 − 직전 7일)`, 기준선 `…감성(직전 7일, 기준선)`). 에이전트 3·4 규칙·적중률은 그대로.
- 중립이면 `reasonCode`: `mixed`(혼재) · `insufficient`(근거 부족) · `weak`(신호 미약).
- **종합 시 주의**: ① `중립(weak)` 은 '약한 신호'이지 '반대 의견'이 아닙니다 — 에이전트 3은 신호가 2개뿐이라 중립이 많습니다. ② `hitRate.status` 가 `unverified` 이면 그 에이전트 결론에는 과거 검증 근거가 없으니 가중에 쓰지 마세요(`measured` 일 때만 `rate`·`n`·`ci95` 참고). 적중률은 #55 결과 파일이 생기면 채워집니다. ③ 세 결론은 근거 키가 서로 다른 영역이라 독립으로 보이지만, 수급과 심리는 같은 사건을 반영할 수 있습니다. ④ 에이전트 6 감성은 정확도 56.6% 기준선, 에이전트 3 은 지표 수정 이력 미보관. ⑤ 결론 확정·가격 수준 표현은 어디에도 없어야 합니다 — 종합 결론에서도 같습니다.

## 200자 요약 `summary200` (에이전트 3·4·6 각각, r4-1.5, #64)
에이전트는 자기 결과를 **공백 포함 200자 이내 한 단락**으로 정리해 오케스트레이터·사용자에게 줍니다. 오케스트레이터는 세 에이전트의 `summary200` 을 받아 종합합니다(기존 `summary`(객체: 핵심 진단 + 근거 ID)는 그대로이며 이름이 겹치지 않게 새 필드를 씁니다).

```json
"summary200": "외국인 20일 순매수 강도 -4.34%로 순매도 우세, 기관은 기준 미달. 세부 투자 주체는 미확보. 20거래일 전망: 부정.",
"summary200Method": "llm"
```
- 구성: **핵심 관찰 1~2개 + 가장 중요한 미확보 1개(있으면)** 뒤에 **20거래일 전망 방향**. 뒤쪽 전망 문장은 코드가 `outlook` 값으로 만들고(`20거래일 전망: <방향>(<사유>).`), 앞쪽 관찰만 LLM 이 씁니다. (#73, 11/9) **과거 검증 판정 꼬리는 요약·답·화면 카드에서 뺐습니다** — 화면 카드에는 '규칙 기반 20거래일 방향(검증 결과는 성능 탭)' 출처 표시만 있습니다. 판정(`hitRate.verdict`·`verdictLabel`·`notice`)은 계약 `outlook.hitRate` 와 시연 성능 탭에는 그대로 있으니, 오케스트레이터는 가중에 쓰기 전에 계속 `hitRate` 를 확인하세요.
- 길이: 값을 실제 숫자로 채운 뒤 `len() <= 200`(공백 포함). 계약 스키마도 `maxLength: 200`.
- 숫자는 장부 키에서만 오며 같은 검사(키 밖 숫자·없는 키·금지 표현·내부 코드·결론/가격 전망)를 통과한 문장만 실립니다. 매수·매도·보유 결론이나 가격 수준은 없습니다.
- `summary200Method`: `llm`(통과) · `llm-retry`(줄여 다시 쓴 뒤 통과) · `llm-trim`(그래도 길거나 일부 문장이 검사에 걸리면 통과한 앞 문장만 남김) · `rule`(규칙 기반 대체: 장부 값 1개 + 전망 — 검사를 통과하지 못했을 때). 빈 요약은 없습니다.
- 옛 결과(r4-1.0~1.4)에는 이 필드가 없으며 그대로 읽힙니다. 전망이 없는 결과는 전망 문장 없이 관찰만 담습니다.

## SW 님과 정할 것
1. 실행 노드 수 규칙(6+N)과 확장 선택 전달 방식(`parameters` 필드 이름).
2. `MAX_REPAIR_ATTEMPTS` 를 오케스트레이터가 정할지 노드 기본값을 쓸지.
3. 다른 팀원 노드(N01~N04, N09·N10)도 같은 NodeTask/NodeResult 를 쓸지.
4. (신규) 종합 규칙에서 `hitRate`·`reasonCode` 를 어떻게 쓸지(SW 몫).

## 문서 검색 방식 변경 (#67, 11/6)
- 에이전트 3·4·6 의 문서 검색 기본값이 **임베딩 중심(벡터 검색 켬)** 입니다(`CH_RAG_HYBRID`, 기본 on, `off` 로 끌 수 있음). 질의응답·시연도 같은 설정입니다.
- 질의 = (질문 +) 종목 + 관점 키워드를 `solar-embedding-2-passage`(1024차원)로 임베딩 → 종목·기준일 이하 청크를 독립적으로 검색 → 키워드 후보와 합침(벡터 유사도 상위 50% 자리를 먼저 보장, 나머지는 키워드·벡터 합산 점수 순). 문서마다 근거 청크(번호·유사도)와 출처(벡터·키워드·둘 다)가 붙습니다. 임베딩 실패 시 키워드 검색으로 대체합니다.
- 계약 필드·출력 모양은 바뀌지 않았습니다(선택 필드만). 켬/끔 측정(에이전트 3·4·6 × 4종목 × 확장 끔/켬 = 24회): 제거 문장 39 → 26, 근거 없는 주장 0 → 0.

## 질의응답 답의 뉴스·공시 인용 숫자 (#66, 11/9)
- 질의응답(`qa/`) 답 문장에 **선택 필드**가 추가됩니다: `태그`(예: `사실(뉴스 인용)`, `사실(공시 인용)`, `해석(뉴스 인용)`)와 `인용`(`[{문서, 날짜, 종류}]`). 인용 문장의 `구분`은 기존 값(사실·계산·해석·예측) 그대로이고, 필드가 없는 기존 소비 코드는 영향이 없습니다.
- 허용 조건: 문서 번호를 달고, 뉴스·공시이며, 숫자가 단위까지 같은 값으로 그 문서 본문에 있고(`1.8조`=`1조 8천억`), 문서 날짜가 기준일 이하. 증권사 목표·가격 수준 숫자는 문서에 있어도 제거. 에이전트 3·4·6 노드의 Verifier는 바뀌지 않았습니다.
- 대상 종목이 있는 질문은 문서 검색을 **항상 1회** 먼저 실행합니다(trace 의 `origin`: `고정 단계(항상 실행)`, 도구 호출 상한 4회에 세지 않음).
- (#72, 11/9) 인용 검사 보강: 만·억·조 뒤 단위(명·건·개·곳·주 vs 원)까지 같아야 통과, 숫자 주변 방향어(순매수/순매도, 증가/감소, 흑자/적자)가 문서와 반대면 제거(문서에 방향어가 없으면 통과). 증권사·기관 전망을 인용한 문장은 `구분`=`예측`, `태그`=`예측(증권사 전망 인용, D#)`이고 문장 끝에 `(전망 인용)`이 붙습니다(가격·목표 수준 전망은 여전히 불허). 문장에 남은 `(사실, 부정, [S1…])` 같은 내부 표기는 저장 전에 지우고 `정리`=`내부 표기 제거` 필드를 남깁니다(선택 필드, 기존 소비 코드 영향 없음).
