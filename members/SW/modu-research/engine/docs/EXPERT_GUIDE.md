# 모두의리서치 — 전문가 모드 설명서 (노드 캔버스, /expert)

> 쉬운 화면(처음 화면) 설명은 저장소 맨 위 README.md에 있습니다. 이 문서는 v0.14까지의 README를 전문가 모드 설명서로 옮긴 것입니다.


6개 관점 × 12개 전문노드(2026-11-02 기본·확장 합의안)를 캔버스에서 연결하고 실행하는 독립 앱입니다.
결과는 매수·매도 의견이나 목표주가가 아닙니다. 원문 사실, 계산, 사용자 가정, 외부 전망을 구분해 보여 주는 조사 도구입니다.

## 실행

| 단계 | 명령 |
|---|---|
| 처음 한 번 | `setup.cmd` (uv와 Node.js 필요. 독립 `.venv` 생성) |
| 시작 | `start.cmd` → http://127.0.0.1:4395/ 가 자동으로 열림 |
| 종료 | `stop.cmd` (이 앱이 만든 종료 토큰이 있어야 종료되므로 다른 앱을 멈추지 않음) |
| 자동 시험 | `test.cmd` |

- 포트: `MODU_NODES_PORT` (기본 4395). 이미 다른 앱이 응답 중이면 **시작을 거절**합니다.
- 데이터: `MODU_NODES_DATA_DIR` (기본 `data/`). 다른 앱의 data를 지정하지 마세요.
- 외부 네트워크 호출, 유료 API, 모델 호출은 없습니다. Ollama 모델도 쓰지 않습니다.

## 처음 사용하기

1. 왼쪽 **조사 계획 만들기**에서 관심 관점을 고르고 **캔버스에 배치**를 누릅니다. 기본 6개 노드에 선택한 관점의 확장 노드가 더해집니다.
2. 「기업가치·실적」을 골랐다면 **T03 사용자 가정 입력**을 선택하고 가정을 채웁니다. 「학습용 예시」는 계산 체험용이며 결과에 항상 *실제 추정 아님*으로 표시됩니다.
3. **검증**으로 잘못된 연결을 확인한 뒤 **실행**합니다. 실행 전에 자동 저장됩니다.
4. 노드를 선택하면 오른쪽 패널의 **결과 / 근거 / 상태·오류** 탭을 볼 수 있습니다. 「근거」 버튼을 누르면 DART 문서, 표·행·열, 문서·표·셀 해시가 보입니다.
5. 새로고침하거나 서버를 다시 시작해도 주소(`#wf=…&run=…`)로 같은 결과를 다시 엽니다.

캔버스 조작: 노드 머리를 끌면 이동합니다. 출력 포트(오른쪽 ●)를 누른 뒤 입력 포트(왼쪽 ●)를 누르면 연결됩니다. 연결선을 누르고 Delete를 누르면 삭제됩니다. 휠로 확대·축소하고 배경을 끌면 화면이 이동합니다. Ctrl+S로 저장합니다.

**연결선은 데이터 전달 관계일 뿐입니다.** 승인, 신뢰, 정답 확인을 뜻하지 않습니다. 실행 순서는 연결 전체에서 위상 정렬로 따로 계산합니다.

## 사업보고서 전체 검색(RAG T1)과 DART 재무데이터(XBRL)

- 원천: `..\_sources\dart_full` (2차_실제/gongsi-research-hybrid의 DART HTML 대목차 원문을 해시 대조 후 복사. 삼성전자 20260310002820, SK하이닉스 20260317000635, 각 15개 대목차). 원본 폴더는 수정하지 않음.
- 「문서·재무」 → 「사업보고서 검색」: 계층 청크(대목차·제목 경로, 표는 행 단위 '열 이름: 값' 형태로 단위와 함께) + BM25(한글 2글자 단위) + 감사 가능한 동의어 표. 결과마다 원문 해시·DART 원문 링크·표 번호·행 범위. 답을 지어내지 않음.
- 임베딩(선택): `prepare-rag.cmd` → 색인 생성 → Ollama 임베딩(기본 embeddinggemma:300m) → 평가. 임베딩이 있으면 BM25+벡터 RRF, 없거나 실패하면 「BM25만」이라고 표시(조용히 하이브리드라고 하지 않음).
- 「검색 평가」: tableaware 앱의 삼성전자 질문 16개로 상위 k개 청크에 기대값이 모두 있는지 측정(검색 단계 지표, 답변 정확도 아님). BM25 기준 @10: 동의어 없음 15/16, 포함 16/16. 동의어 표는 질문을 본 뒤 작성되어 완전한 미사용 평가가 아님.
- 「DART 재무데이터(XBRL)」: OpenAPI 단일회사 전체 재무제표를 가져와 표준 계정(ifrs-full_Revenue 등)으로 매출·영업이익·순이익·현금흐름·자산·부채·자본·EPS를 만들고, N01 표 값과 자동 대조(불일치는 표시만, 자동 수정 없음). 키는 `local-env.cmd`의 `DART_API_KEY`로만 설정. 응답은 해시와 함께 `data\xbrl`에 저장되어 재호출하지 않음.

## 에이전트 (v0.1 — 1~4단계)

에이전트는 기존 노드를 고치지 않고, 사람과 같은 「검증 → 실행 → 결과 조회」 창구를 쓰는 바깥 층입니다. 전망 승인·매매 판단·공식 원문 값·기준시점은 바꾸지 않습니다.

1. **에이전트 실행 (자기 수정 실행기)** — 실행 → 노드 상태·이유 코드 읽기 → 규칙표(R01~R20, 모르는 상황은 R99로 사람에게)대로 고쳐 재실행 → 멈춤. 최대 4회. AI 모델을 쓰지 않습니다. 「규칙표 보기」에서 전체 규칙과 원칙을 볼 수 있습니다.
   - 자동 수정 예: 보고서 미선택 → 원칙(승인 완료·최근 순·다른 증권사 우선)대로 선택, N02에 필요한 사실 없음 → N01 조사 항목 추가, N02 범위 밖 → N01 범위 추가
   - 사람에게 넘김 예: 고른 보고서에 승인 없음(몰래 바꾸지 않음), PDF 변경, 기준시점 문제
   - 중단 예: 원문 재대조 불일치, 무결성 오류
2. **근거 검증 관문** — 에이전트 요약은 패킷에 연결된 슬롯으로만 만들고, 표현 검사기(v0.3.2, 계산값 슬롯 {{val:}} 추가) 보수 모드로 검사합니다. 근거 없는 숫자·원문 불일치·검증 불가 판단·매매 표현이 있는 문장은 보류됩니다. 다른 글도 `/api/agent/gate`로 같은 관문을 통과시킬 수 있습니다.
3. **질문으로 시작하기 (계획 에이전트)** — 질문 한 줄 → 검증된 사례 4개 중 하나를 고름 → 「배치하고 에이전트 실행」. 기본은 키워드 계획이며, AI 모델은 선택입니다: `local-env.example.cmd`를 `local-env.cmd`로 복사해 주소·모델명을 넣으면 start.cmd가 읽습니다. 모델 답이 목록 밖이면 버리고 키워드 계획을 씁니다. 키는 서버에서만 쓰입니다.
4. **이의 제기 → 재심의** — 실행이 끝난 뒤 T03(가정)·T04(보고서 선택)·N02(전망 적용)·N01(사실 재대조) 노드에서 「이의 제기」. 사유는 필수이며 기록됩니다. 같은 기준시점으로 바꾼 구성을 에이전트가 다시 실행하고 주당가치 전후·상태 변화·원문 재대조 결과를 비교합니다. 원래 실행은 바뀌지 않습니다. 공식 원문 값은 바꿀 수 없습니다.

되돌리기: `..\_releases\` 아래 버전별 폴더(v0.2-stable에 restore.cmd)와 NOTES.md를 보세요.

## 예시 사례와 내 유형 (v0.1)

- 「예시 사례」(또는 빈 캔버스의 버튼)에서 노드가 연결된 사례 4개 중 하나를 불러옵니다. 각 사례는 「답하는 질문 → 노드별 역할·값의 종류 → 결과 읽는 법 → 주의」로 설명됩니다.
  1. 공시로 확인된 실적만 보기 (T01→N01→T05) — 입문·좁게
  2. 실적과 거시 환경 함께 보기 (T01→N01·N05→T05) — 입문·넓게
  3. 증권사 전망 한 건으로 기업가치 계산 (T01·N01·T03·T04→N02) — 숙련·좁게
  4. 증권사 3곳 전망을 같은 가정에 넣어 비교 (N02 3개 → T05) — 숙련·넓게
  5. 정상화 이익 시나리오 (같은 전망 1건 + 정상화 FCFF 150/250/350조 → N02 3개 → T05)
- N02 결과에 말기가치 비중이 60% 이상이면 「해석 안내」가 붙습니다(전망 차이가 결과에 덜 반영되는 이유). 에이전트 요약에도 말기가치 비중 문장이 들어갑니다.
- 전망이 필요한 사례는 2026·2027 매출액·영업이익이 승인된 보고서를 최근 순(서로 다른 증권사 우선)으로 T04에 자동으로 넣습니다. 부족하면 안내합니다.
- 「내 유형」은 3문항(공시 읽은 경험, 가치평가 계산 경험, 좁게/넓게)으로 정합니다. 바뀌는 것은 추천 순서와 설명의 양뿐이며, 사실·전망·계산 결과는 누구에게나 같습니다. 투자 성향(위험 선호) 분류가 아닙니다. 답은 브라우저에만 저장됩니다.

## 기대 부채 지수 EDI (N17, v0.19 · KIRI 시간자본론)

주가가 「실적이 받치는 가치(V)」보다 미래 성장을 몇 년치 미리 반영했는지를 햇수로 보여 줍니다. 쉬운 화면 카드 「주가가 실적보다 몇 년 앞서 있나?」 = T06(1300거래일) + T11 + T13 → N17.

- **식:** V = 자본 × (ROE − 장기성장) ÷ (r − 장기성장) ÷ 주식 수 (잔여이익 영구 성장형), EDI = ln(주가 ÷ V) ÷ ln(1 + g). EDI = n이면 「실적이 연 g씩 n년 자라야 지금 주가와 맞는다」.
- **V 세 가지를 나란히:** 정규화(최근 12분기 평균 ROE) · 최근 4분기 ROE · 장부가. 경기순환 업종은 방식에 따라 결론이 정반대가 될 수 있어 하나로 단정하지 않습니다.
- **그때 알 수 있던 것만:** 날짜마다 분기 말 + 45일이 지난 분기만 씁니다. ROE가 장기성장률 이하이면 그 방식은 보류(0으로 채우지 않음).
- **지금 주가가 요구하는 ROE:** V = 주가가 되게 하는 ROE와 필요한 연 순이익. 실제 ROE와 나란히 봅니다.
- **증권사 전망이 맞다면:** T13 원장을 이으면 올해·내년 영업이익 승인 전망 집계 중앙값 × 최근 4분기 순이익/영업이익 비율(가정)로 전망 ROE를 만들고 같은 식으로 계산합니다. 목표주가는 쓰지 않습니다.
- **최고점 이후 상환 분해:** 불러온 기간의 EDI 최고점에서 지금까지 줄어든 몫을 V 상승(실적)과 주가 하락으로 나눕니다(ln 분해, 원인 단정 아님).
- **설정:** 자기자본비용 r(기본 9%), 장기성장률(2%), EDI 기준 연 성장률 g(8%), 보통주 외 주식 수(우선주 등). 자본에는 우선주 몫이 들어 있으므로, 우선주가 있는 회사는 이 칸을 채워야 주당 V가 과대해지지 않습니다(삼성전자 우선주 약 8.15억 주 — 직접 확인 후 입력).
- **값의 종류:** V·EDI·요구 ROE·상환 분해는 「학습용 예시 가정」(주황), 전망 환산은 「증권사 외부 전망」(주황), 쓴 자료는 「공식 원문 확인 사실」, ROE는 「계산 파생값」.
- **하지 않는 것:** 적정주가·목표주가·매매 판단. V는 가정 아래 계산값이라는 문장이 답 카드의 「일부러 하지 않는 것」에 항상 붙습니다.
- **v0.20 분기 자료:** 분기 표가 없는 회사도 DART 분기·반기·사업보고서(접수번호의 실제 접수일)로 분기 자본·순이익을 만들어 씁니다(4분기 = 연간 − 3분기 누적). 정정 공시는 정정일이 공개일로 잡힙니다.

### 실적·가격 격차 국면 기록 (N18, v0.20)

같은 카드에 함께 붙습니다. 실적이 반영된 날부터 다음 실적이 반영된 날까지를 한 구간으로 보고, 구간마다 주가 변화(a)와 V 변화(b)로 판정합니다.

| 국면 (앱 표기) | 규칙 | KIRI 콘텐츠 표기 |
|---|---|---|
| 가격이 실적보다 앞섬 | EDI가 1년 이상 오름 | 기대 차입 |
| 실적과 함께 움직임 | EDI 변화 1년 미만, V 상승 | 실적 동반 |
| 실적 주도로 격차 축소 | EDI가 1년 이상 내림, 줄어든 몫의 70% 이상이 V 상승 | 건강한 상환 |
| 실적·가격 함께 격차 축소 | 실적 몫 30~70% | 혼합 상환 |
| 가격 주도로 격차 축소 | 줄어든 몫의 70% 이상이 주가 하락 | 강제 상환 |
| 실적·가격 동반 하락 | a < 0, b < 0 | 실적 악화형 |
| 실적 수준 아래로 더 내려감 | 시작 EDI ≤ 0에서 더 내려감 | 저평가 심화 |
| 변화 작음 | EDI 변화 1년 미만, V 그대로·하락 | 변화 미미 |

정규화 V와 최근 4분기 V의 「누가 움직였나」가 다르면 「가정에 따라 갈림」, ROE가 장기성장률에 2%p 안으로 가깝거나 재무가 분기 말에서 185일 넘게 지났으면 「판정 보류」. 마지막 열린 구간은 「진행 중」으로 판정하지 않습니다. 앱 안에서는 왼쪽 중립어만 씁니다(시험으로 고정).

## 표현 검사기 (규칙 v0.3)

상단 **표현 검사** 버튼을 누르면, AI 답변이나 리포트 문장 속 숫자·판단 표현을 찾아 색으로 표시합니다. 규칙은 상위 폴더 `_spec/numeric-expressions-v0.3.md`에 있습니다.
- **연구 모드(기본):** 막지 않고 표시만 합니다. 매매 지시 단어만 숨깁니다. 이 모드에서는 "모델이 숫자를 지어낼 수 없다"가 보장되지 않습니다.
- **보수 모드:** 검증되지 않은 수치·판단이 들어 있는 문장은 보류합니다.
- 슬롯 `{{fact:ID}}`, `{{calc:pct(a,b)}}`, `{{cmp:a,b}}`, `{{period:ID}}`을 쓰면 코드가 검증된 값으로 채웁니다. `{{ext}}`(외부 전망)와 `{{quote}}`(원문 인용)는 자료원이 연결되면 동작합니다.
- 정도 표현 기준(연구용 시작값): 30% 이상 「급」, 10~30% 「대폭」, 3~10% 증감, 3% 미만 「소폭」 — `mrn/numeric.py`의 `DEGREE_BANDS`에서 바꿀 수 있습니다.
