## 3. 검증
**자동 시험 23개, 모두 통과.** 컨테이너(Python 3.13)와 사용자 PC 작업 VM(Python 3.10)에서 각각 실행했다. ResourceWarning을 오류로 취급하는 설정에서도 통과했다.
- 등록부: 12노드, 기본/확장, 미연결 사유 필수
- 계획 수 6/9/12, 선택하지 않은 관점의 확장 노드는 0개
- 잘못된 연결 거절: 자료형 불일치, 필수 입력 누락, 순환, 기준시점 혼합, N06←N05 외 입력, 가정 오류(g≥r), 단일 포트 중복, N02 범위 밖, 미승인 외부 전망
- 실제 공시 흐름: 셀 근거, 종류 배지, origin_ref
- 변조: 해시를 갱신하지 않은 경우 → 무결성 오류로 보류. 해시까지 갱신한 값 변조와 표 해시 변조 → 원문 재대조에서 보류
- 좁은 할인율−성장률(6%/4.5%) → 경고. 민감도 25칸 모두 입력 해시가 있거나 보류이고, g≥r 칸은 보류
- 미연결 노드 → 패킷 없음, 보고서에도 「미연결」로 기록
- 기준시점 2026-10-01(자료판 이전) → T01 보류, 하위 노드도 보류로 전파
- 취소: 완료된 T01 결과는 유지, 진행 중이던 N01과 이후 노드는 취소, 엔진 잠금 해제
- 재시작: 진행 중 실행은 중단으로 기록, 완료 결과와 이름 변경 이력은 동일
- CSRF 헤더 누락, 다른 소유자, 외부 Origin → 거절
- 포트 사용 중 감지

**브라우저(헤드리스 Chrome, 1600×950) 점검:** 계획 배치, 잘못된 자료형 연결 즉시 거절, 학습용 예시 입력, 실행, 새로고침 후 같은 결과, 서버 재시작 후 같은 결과, N02 결과와 근거(DART 접수번호·표·행·열·해시), 필수 연결 삭제 → 실행 차단, 편집 후 「이전 실행」 표시. 콘솔 오류 0건.

**운영 점검:** 잘못된 종료 토큰 거절(403), 같은 포트 두 번째 실행 거절(종료 코드 3), 종료 직후 재시작 성공

**보존 확인:** `2차_실제`의 재사용 후보 7개 앱 소스와 AGENTS.md 898개 파일의 SHA-256이 작업 전과 같다(변경 0).

## 4. 검증하지 않은 것
- **Windows에서 `setup.cmd`/`start.cmd`를 실제로 실행하지 않았다.** 작업 환경이 Linux여서 PowerShell 스크립트는 기존 4373 방식을 따라 작성만 했다. 처음 실행할 때 확인이 필요하다.
- 내장 브라우저에서 4395 화면 확인(서버가 Windows에서 실행된 뒤 가능)
- 금융 정확도, 투자 성과, 일반 사용자 사용성. 시험은 기능 계약만 확인한다.
- 390px 모바일 화면 대응(이번 판은 데스크톱 캔버스 기준)

## 5. 개발 중 발견하고 고친 결함
1. 기준시점을 비워 두면 "실행 시각을 쓴다"고 안내하면서 검증에서는 오류로 막았다 → 경고로 바꾸고, 일부 T01만 지정된 경우는 혼합 오류로 처리
2. N01이 등록부의 기본 항목 대신 처리기 내부 기본값을 썼다 → `with_defaults` 한 곳에서 기본값을 관리
3. SQLite 연결이 닫히지 않았다(Windows 파일 잠금 위험) → 커밋·롤백·닫기를 보장하는 컨텍스트로 변경
4. 종료 직후 재시작하면 TIME_WAIT 상태를 "포트 사용 중"으로 오판해 시작을 거부했다 → 실제로 응답하는 앱이 있을 때만 거부
5. N02 경고 10개 중 결과에 따라 달라지는 경고(말기가치 93.7%)가 고정 전제 문구 사이에 묻혔다 → 결과별 경고만 위에 두고 고정 전제는 접음

## 6. 사양 v0.1과 달라진 점
- T02(시점 검사)는 별도 노드가 아니라 엔진과 T01에 넣었다. 기준시점 혼합, 자료판 이전 시점, 미래 시점을 모두 검사한다.
- N09는 「일부」 대신 「미연결」로 정했다. 실가격 자료원이 없어서 합성 예시로 동작하는 것처럼 보이지 않게 했다.
- 민감도 경고 기준: 4373의 1%p 경고는 그대로 두고 2%p 경고를 추가했다. 말기가치 비중 경고는 4373 원래 기준(70%)을 유지했다.
- 미연결 자료 도구 T06~T09를 추가했다. 미연결 노드도 캔버스에서 타입이 맞게 연결할 수 있도록 하기 위해서다.
