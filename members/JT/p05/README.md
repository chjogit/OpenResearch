## 무엇이 들어 있나

**claims(주장)**
- 판정이 난 항목만 들어갑니다.
- 규칙 판정: 삼성전자는 지배구조 규칙 G01~G13과 약속–실행 규칙 PE01을 씁니다. 다른 회사는 PE01만 씁니다.
- 공시 사실: 취득한 자사주가 소각으로 이어졌는지, 법원 결정·이사회 결의가 있었는지입니다.

**P05 고유 필드(최상위)**
- `promiseExecution`: 약속–실행 대조표입니다. 자사주 취득 결정과 결과보고서, 기업가치제고계획 목표를 맞댑니다.
- `capitalAllocation`: 자본배분 연표입니다. 배당·자사주·소각·투자·재편 공시를 날짜순으로 담습니다.
- `issues`: 쟁점과 해명입니다.
  - 공시: 풍문 해명, 조회공시, 소송 공시입니다.
  - 보도: 주제별 묶음입니다. 기사 제목은 넣지 않고 doc_id와 건수만 둡니다.
- `governance`, `personSentiment`, `handoff`: 앞서 쓰던 P05 고유 필드입니다.

**unverified(미확인)**
- 판정 보류된 항목을 담습니다. 기업가치제고계획 숫자 목표, 진행 중인 취득, 보도 쟁점 묶음입니다.
- 검증 전 감성도 여기에 들어갑니다. 대상 감성은 모두 `UNVALIDATED`입니다.

## 판정 규칙의 한계

- 기준값은 모두 팀 합의 전 초안입니다(`thresholdStatus: draft`).
  - 약속–실행: 95% 이상 이행, 50% 이상 부분 이행입니다.
  - 지배구조: 컨센서스 97% 이상, 보상용 매입 50% 이상, 소각 95% 이상 등입니다.
- 주장 문장에는 날짜와 기준값 말고는 숫자를 쓰지 않습니다. 숫자는 근거(evidence) 값에 있습니다.
- 기업가치제고계획 항목과 보도 주제는 규칙으로 뽑았습니다. 사람 확인이 필요합니다.
- 보도 건수는 네이버 검색 1,000건 제한 영향이 있습니다. 크기 비교가 아니라 존재 확인용입니다.
- 삼성전자 G07(보도·의결액 기준)과 자본배분 연표(공시 결정 금액)는 같은 자사주를 다른 기준으로 잽니다(`SAME_TOPIC_DIFFERENT_BASIS`).

## 팀 확인이 필요한 것 (OpenResearch #41)

1. **에이전트 번호**: 5번과 모듈명 `agent5_governance`는 가정입니다.
   - `nodes.py`에는 3·4·6번만 있습니다.
   - `agent.agentNos`는 허용값이 3·4·6뿐이라 넣지 않았습니다.
2. **받는 방식**: 오케스트레이터가 이 JSON 파일을 읽을지, 함수 반환값을 받을지 정해야 합니다.
3. **handoff 대상 번호**: 가치·위험, 2번 사업모델의 새 번호를 모릅니다. 그래서 이름으로 적었습니다.

## 다시 만드는 법

이 폴더의 코드는 검토용 사본입니다. 실행은 JT의 P05 작업 폴더에서 합니다.
그 폴더에 `.env`, `data/`, DART 원문 캐시가 있기 때문입니다. 셋 다 저장소에 올리지 않습니다.

```text
python scripts/promise_execution.py            # 약속–실행 대조표
python scripts/capital_allocation_timeline.py  # 자본배분 연표
python scripts/issue_response.py               # 쟁점과 해명 (DB 읽기만)
python scripts/export_notebook_rules.py        # 삼성전자 지배구조 노트북 규칙 13개 내보내기
python scripts/build_governance_contract.py    # 회사별 P05 원본 → 팀 계약 r4-1.3, 검사 통과 시에만 저장
```

- 필요한 값: `DART_API_KEY`, `DATABASE_URL`(p05 쓰기 계정, 이 단계에서는 읽기만)
- 투자 권유가 아닙니다.
